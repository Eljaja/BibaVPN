BibaVPN — backlog / design notes (discussion takeaways)
=========================================================

1. What is already distinctive in the current protocol
------------------------------------------------------
- Layer on top of WSS, not a standalone IETF protocol.
- Logical channel: custom OPEN (magic BIBA\x01OPEN\x00 + host + port); server skips
  binary frames until a valid OPEN; random junk rarely collides with the fixed magic.
- Optional junk frames after the WebSocket upgrade (client).
- Inner frame: [ver][len u24][pad_len][random pad][payload] — variable size (AmneziaWG-style shaping).
- Browser-like HTTP upgrade (UA, Origin, Sec-WebSocket-Extensions, Accept-Language).
- Token in path /b/{token}.
- Optional BibaV2: HELLO/ACK (BLAKE3 MAC), ChaCha20-Poly1305, split c2s/s2c keys,
  decoy in plaintext before AEAD (AWG2-inspired); not compatible with stock WireGuard/Xray.
- Intended to run alongside zapret on Linux routers.

2. From AmneziaWG (incl. 2.0) — possible additions
---------------------------------------------------
- Junk like AWG: jc, jmin, jmax instead of a fixed 32..512 range; respect MTU
  (avoid sizes that trigger suspicious IP fragmentation).
- Phase-specific padding (S1–S4 analogue): handshake vs transport (today mostly
  max_pad on payload; HELLO/ACK lack the same variable tail).
- H1–H4 idea: fewer fixed on-wire magics — phase/type from a negotiated range
  derived from PSK + ephemeral (harder, weaker static signatures).
- Concealment packets (I1–I5 analogue): templated frames (static bytes, random,
  timestamp-like block) — not only raw OsRng.
- Padding on HELLO/ACK (S1/S2 analogue).

3. From Xray / v2ray codebases — ideas for BibaVPN
---------------------------------------------------
- uTLS / fingerprint presets: rustls + browser-ish HTTP headers still differ from Chrome JA3;
  uTLS-like layer or external proxy.
- REALITY: TLS masquerading; for Biba at least document «biba behind REALITY proxy»;
  full in-tree support is a larger project.
- Early data for WS: bytes in Sec-WebSocket-Protocol (base64), delayed dial — softens
  startup pattern (junk/HELLO/OPEN zone).
- Configurable WS Host/Origin/headers instead of a single hardcoded preset.
- WebSocket heartbeat — periodic frames vs idle/NAT and «silence → spike» heuristics.
- Optional browser dialer for WS where maximum plausibility matters.
- TCP mask / fragment below TLS — changes byte pattern on TCP (Xray finalmask class).
- splitHTTP-style «tokenish» padding if transports beyond bare WSS appear.
- Mux: today roughly one SOCKS flow ↔ one WSS; multiplexing cuts reconnect/upgrades pattern.

4. Popular DPI circumvention themes (context)
---------------------------------------------
- «Looks like normal web»: HTTPS, WS/H2/gRPC, ECH where SNI is filtered.
- «TLS like a browser» / QUIC with the same goal.
- REALITY-class fronting.
- QUIC/UDP stacks (Hysteria, TUIC, HTTP/3) where UDP is allowed.
- WireGuard + obfuscation (AmneziaWG, etc.).
- DoH/DoT wrapping, spare tunnels (SSH, …) — niche.
- Local IP/TCP tricks (zapret/nfqws): fragmentation, segment ordering — below app TLS.
- Tor + pluggable transports — different stack, same ideas.
- Distributed nodes / CDN / IP rotation — ops, not a single protocol trick.

5. System questions (when designing)
------------------------------------
- Where filtering happens: IP, SNI/ECH, TCP size/timing, TLS fingerprint, «VPN-like» heuristics.
- Egress DPI at user ≠ ingress DPI at server.
- Fixed bytes and message order age into rules; ranges and secrets-derived params age slower.
- Cap junk/decoy/pad with MTU and fragmentation in mind.
- Behaviour: reconnect rate, parallel flows, keepalive — not only crypto.
- Operations: home vs mobile networks, resolvers — affects «what works».

6. Prioritization sketch
------------------------
- High leverage: uTLS or browser dialer; flexible WS headers; early data; heartbeat;
  mux; careful junk/decoy/MTU caps; relax fixed BibaV2 magics.
- Medium term: optional TCP-mask layer; templated junk; split pad for handshake vs data.
- Deploy without bloating code: REALITY/Caddy docs in front of biba; zapret sidecar.

This file is not a spec — ideas for discussion and prioritization.
