# yb-mesh implementation

The acceptance criteria are in the supplied yb-mesh guide. Keep the current
profile's direct address, TLS name, credentials, certificate pin and routing
rules unchanged when mesh is selected. Never fall back to the direct address.

1. Extend encrypted invites with optional `yb_mesh.endpoint`; test old and new
   serialization and accept only Yggdrasil IPv6 socket addresses at use time.
   Wire invite creation and copy the endpoint into the saved profile while
   preserving the user's separate per-profile switch.
2. Integrate a pinned yggstack-ng and Yggdrasil-ng core. Start one node per
   running client, dial its userspace TCP stack, and stop all its tasks when
   the client exits. Bootstrap multiple peers, determine availability from
   completed peer handshakes, and replenish failed peers without dropping
   working ones. Limit the candidate pool and concurrent attempts.
3. Route tunnel TCP, UDP mux, periodic and idle decoys and latency checks
   through one selected opener. Test failure with mesh enabled and verify that
   no direct connection is attempted. Preserve TLS verification and WS host.
4. Protect every external peer socket before connect on Android, including
   reconnects; exercise network changes. Add the per-profile toggle, persist
   it, reconnect when changed and report unavailable mesh with a retry action.
5. Provide an optional persistent server mesh sidecar, make the installer
   advertise its stable address, then run Linux end-to-end TCP, UDP, latency,
   decoy, failover, and direct-address-block tests; check Android builds and
   device behavior where hardware is available.

Research finding: the pinned upstream core creates peer TCP sockets internally
without an Android protect hook. It must be extended at the socket creation
point before Android mesh can be considered safe. QUIC must either be
protected too or excluded from the candidate pool.
