# BibaVPN connection troubleshooting

Diagnose in order; preserve the original configuration and redact credentials and invitation URIs from any logs. `check-connection.sh` exits 0 for an HTTP response accepted by curl, 1 for a failed request, and 2 for invalid arguments. It suppresses the response and curl's detailed error because URLs may contain secrets. Its 5-second connect and 15-second total limits make it a quick check, not a performance measurement.

1. **Local proxy:** confirm the client is running and listening on the expected address and port. The README's Docker lab uses `127.0.0.1:11080`; its source client example uses `127.0.0.1:1080`. Check container status or client logs without exposing secrets. Curl exit 7 commonly means a local proxy connection failed; 28 means a timeout.
2. **Target and SOCKS:** use an explicitly chosen reachable HTTP(S) target. The script uses SOCKS5 remote DNS and overrides `NO_PROXY` so the check cannot silently use a direct route. Exit 22 indicates an HTTP error from the target, while 97 indicates a SOCKS negotiation failure; inspect the target's behavior and client logs before concluding the VPN is down.
3. **Server/TLS:** verify the server address, port, SNI, certificate chain and pin against the deployed configuration. Curl exit 60 can indicate certificate verification failure at the HTTP target; client TLS errors must be investigated in client logs. Use a valid certificate or an intentional pin, not `--insecure` for remote operation.
4. **Authentication:** check that client and server use the matching PSK, token and protocol version without displaying them. For a users file, check the selected user is enabled and below its session limit. Reloaded access changes affect new sessions; an existing session is not disconnected. Each TCP tunnel and separate UDP session consumes a slot, and counters are per server process.
5. **REALITY:** verify target/SNI, server public key, short ID, compatible client/server versions and clock synchronization. REALITY in this project is its own WSS handshake, not Xray compatibility; read the repository's protocol documentation for details.
6. **Limits of this test:** a successful HTTP request does not test UDP, all apps, IP anonymity, or DNS leak protection. Run a task-specific test when those properties matter. For code changes, use the checks in the repository's `AGENTS.md`.
